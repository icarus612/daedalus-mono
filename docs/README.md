# Daedalus Monorepo — docs

`daedalus-mono` is a **pnpm + turbo monorepo** holding three per-language package managers under one
task runner (S3, see [`package-management-strategy.md`](./package-management-strategy.md) for the
full decision record — D1). Concretely: **pnpm workspaces** for JavaScript/TypeScript
(`libs/javascript/**`, `apps/next/**`), **per-package Poetry virtualenvs today, migrating to a
single root `uv` workspace once Phase 2 lands** for Python (`apps/flask/**`,
`apps/microservices/**`, `libs/python/**`), and **`go.work`** for Go (`libs/golang/**`). All three
are driven through `turbo`, using the repo's `package.json`-as-universal-task-shim convention (#4 in
the plan's Conventions section) — every project, JS or not, carries a `package.json` whose
`dev`/`build`/`lint`/`test` scripts shell out to the real per-language toolchain, so one `turbo`
invocation spans all three languages.

## Quickstart

```bash
git clone <this-repo>
cd daedalus-mono

# Installs JS deps AND triggers every Python project's `py-install` lifecycle script today
# (Phase 2's subphase 2.5 will replace the per-package venvs with one root `uv` workspace —
# see package-management-strategy.md; until then this is the real, current mechanism).
pnpm install

# Go needs no separate install step — go.work gives local cross-module resolution.
go build ./...   # run from inside a libs/golang/<module> directory, see installation.md

# Run everything, or scope to one package by its dotted turbo name
# (convention #2 — the name mirrors the path: lib.golang.err, app.flask.pokedex, ...):
pnpm turbo build
pnpm turbo lint
pnpm turbo test
pnpm turbo build --filter='lib.golang.err'
```

See [`installation.md`](./installation.md) for the exact, verified per-language commands (including
the caveats each language currently carries), [`package-management-strategy.md`](./package-management-strategy.md)
for why this three-workspace shape was chosen over the alternatives, and
[`development.md`](./development.md) for the day-to-day script table.

## Finding a package

The root [`README.md`](../README.md)'s **Project Structure** tree (auto-generated by
`libs/bash/github-actions/create-mono-file-tree.sh` on every push to `main`, via
`.github/workflows/update-readme.yml`) is the map of every `apps/**`/`libs/**` project — each linked
entry is a directory with its own `README.md`. This docs root does not duplicate those per-package
references; it only covers repo-wide install/strategy/command concerns.
